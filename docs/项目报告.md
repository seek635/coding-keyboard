## 一、项目概览

### 1.1 一句话定位

一款**蓝牙（BLE）编程专用实体小键盘**，11 键 + 侧边审批拨杆，把 Claude Code 里最高频的操作从键盘组合键变成单手一按。

### 1.2 核心设计目标

> **键盘本身不改变 Claude Code 的任何行为。** 拨杆 OFF 时它就是一个普通键盘；拨杆 ON 时才介入。

这一条决定了整个产品的技术路线——不是"劫持"终端，而是通过**官方 hooks 接口**在用户明确授权时提供便利。

### 1.3 键位

```
┌──────────┬────┬──────┬────────┬────────┐
│ 访问等级  │ ↑  │ 模型  │ 命令行  │  停止   │
├────┬────┬────┴────┴────────┤        │
│ ←  │ ↓  │ →    │   回车 2u   │        │
├────┴────┴──────┴────┬───────┴────────┤
│      空格 4u        │      语音       │
└─────────────────────┴────────────────┘
                                    ╱ 审批拨杆（OFF / ON）
```

- **11 个物理键** + 1 个侧边拨杆
- 三行五列网格；**方向键保留传统十字排列**（最高优先级约束）
- 大键：空格跨 4 格、回车跨 2 格

### 1.4 整机参数

| 项 | 值 |
|---|---|
| 尺寸 | **107.10 × 71.10 × 23.10 mm**（X 向 111.20 含右侧拨杆凸台） |
| 主控 | nice!nano v2（nRF52840） |
| 轴体 | Kailh Choc 矮轴 35–40g，**共 14 个** |
| 供电 | 3.7V 锂电 300–500mAh |
| 固件 | ZMK（shield 配置） |
| 连接 | BLE HID over GATT |

## 五、关键设计决策

### 5.1 键盘是无状态的

键盘收不到权限档位、模型名、审批状态。所以「长按复位到 default」「长按循环切换模型」**键盘做不了**——它不知道当前在哪一档。

**方案**：键盘只**发信号**（`Ctrl+Alt+Shift+F13`/`F14` 这种极难误触的组合），由读取终端状态栏的上位机执行真正的操作。

### 5.2 审批拨杆走 hooks，不走文本嗅探

| | 终端文本嗅探 | Hooks（采用） |
|---|---|---|
| 稳定性 | 匹配文案，**改文案就失效** | 官方接口，不依赖文案 |
| 能否分级 | 难结构化 | 直接拿到 `tool_name` + `tool_input` |
| 误判 | 天然会误判 | 结构化字段，无误判 |

**官方机制的关键一条**：

> `PreToolUse` 返回 `{"hookSpecificOutput":{"permissionDecision":"allow"}}` → 跳过权限提示
> **返回空（exit 0 无输出）→ 不算批准** → 走原生权限流程

这使「拨杆 OFF = 产品不存在」成立。

**两条铁律**：
1. **失效安全** —— 任何故障（进程没跑 / 令牌错 / 脚本异常）都退化为「正常询问」，绝不误批
2. **只升不降** —— hook 只返回 `allow`，从不返回 `ask`/`deny`

### 5.3 大键必须多轴支撑

| 方案 | 4u 空格 PLA 挠度 |
|---|---|
| 单轴支撑 | **1.487 mm**（明显翘） |
| **三轴并联** | **0.186 mm**（降 87.5%） |

回车 2u 用 2 轴，空格 4u 用 3 轴。**这不是可选项**，是数值证明的必需项。

### 5.4 键帽间隙必须 ≥ 键程

键帽裙边 **17.6mm** 比定位板轴孔 **13.8mm** 宽——**裙边塞不进孔里**，键帽只能悬在板上方。所以下压空间必须靠「键帽底面到定位板」的间隙提供：

```
CAP_GAP = SWITCH_TRAVEL(3.0) + 0.3 = 3.30 mm
```

写成 0.3mm 会让键盘**完全按不下去**。这一条是在审查渲染图时发现并修正的。

### 5.5 单一数据源

**所有尺寸只有一个来源：`cad/lib/params.scad`。** 校验脚本、PCB 网表、行程图、三维查看器全部解析它，不手抄。

## 七、风险与未验证项

### 7.1 高优先级（阻塞制造）

| 风险 | 影响 | 应对 |
|---|---|---|
| **★ 主控在板面上放不下** | 板面 86×50 被 14 个轴体占满，17.8×33 的主控**零重叠位置数 = 0**。已与 4 个轴体重叠 322.52 mm² | 主控移到 **PCB 背面**（x=68, y=8.5），同步挪支撑台 70→52、下移 USB 开孔。详见 `docs/PCB设计规格书.md` §14 |
| **`SWITCH_PLATE_GAP` 未知** | Choc 官方未公开定位板高度，社区实测 3.5–6.0mm 浮动。取错会导致轴体装不上或主控放不下 | 已做**校准试件** `00_test_coupon.stl`（3 个测试位），**15 分钟打印即可实测** |

### 7.2 中优先级

| 风险 | 说明 |
|---|---|
| **固件未编译** | 本地无 Zephyr 工具链。语法依据官方文档逐条核对 + 静态校验，首次构建可能需微调 |
| **审批拨杆未真机验证** | 本机无 Claude Code CLI，验证在协议层完成。接入步骤见 `docs/审批拨杆技术验证.md` §7 |
| **PCB 未打样** | 封装坐标已交叉验证，但未生成实际 PCB 文件跑 DRC |

### 7.3 低优先级

| 风险 | 说明 |
|---|---|
| 拨杆型号差异 | 不同型号轴套尺寸可差 2mm。买回后量三个尺寸（轴套直径/长度/面板），对不上改 `params.scad` 的 `SW_*` 参数 |
| 打印公差 | 轴孔 13.80 → 打印需设 **13.90~13.95**。这是唯一错了就整机报废的尺寸 |

### 7.4 设计过程中发现并修复的严重问题

| 问题 | 后果 | 发现方式 |
|---|---|---|
| 键帽间隙写死 0.3mm | **键盘完全按不下去** | 用户看渲染图发现 |
| 内腔高度写死 9.0mm | 定位板抬高 4.2mm，轴体够不到 PCB | 自写脚本检查发现 |
| USB-C 开口方向错 | **USB 口插不进去** | 渲染右壁正视图发现 |
| PCB 支撑台顶住轴体塑料脚 | 装不进去 | 计算轴体空隙发现 |
| 底座 STL 非水密 | 切片软件报错 | STL 校验脚本发现 |

> **教训**：「零件之间不干涉」不等于「机构能动」。静态装配检查全过，但运动部件的行程没检查。
> 任何有相对运动的部件，都必须校验「它能否走完整个行程」。
