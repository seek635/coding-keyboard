## 1. 背景与目标

### 1.1 背景

PCB 打样卡在「没有板文件」：`pcb/` 目录只有 `netlist.json` / `netlist.md` / `placement.csv` / `wiring.svg`，
没有任何 `.kicad_pcb` / `.kicad_sch` / `.kicad_pro`，也没有 Gerber。

`docs/PCB设计规格书.md` §12 自己声明了这条边界：「本文件给的是**设计规格与坐标**，画板需要你在 KiCad 里落地」。

### 1.2 目标

产出一个**能在 KiCad 中打开、DRC 通过、封装放置正确**的板文件，坐标全部来自 `cad/lib/params.scad`
的派生数据，供用户手工布线后打样。

### 1.3 关键约束

- 封装几何**不能由本项目手抄**。手抄的封装即使错了，DRC 也查不出来，但板子会做废 ——
  必须从 KiCad 官方库加载真封装。
- 坐标**不能有第二份来源**。`params.scad` 是唯一数据源，`gen_pcb.py` 已经从它算出全部坐标，
  新生成器只能读它的产物，不能重算。

---

## 2. 非目标

明确不做：

- ❌ **不布线**。生成的是「封装已放好、网络已连（有飞线）」的板，走线由用户在 KiCad 里手工完成
- ❌ **不出 Gerber**。布线完成后才能出
- ❌ **不生成原理图**。只在 `.kicad_pcb` 内部直接给焊盘指定网络
- ❌ **不含 WS2812**。v1 不放灯珠，只保留 D15 焊盘备将来使用
- ❌ **不做实机验证**。物理验证（校准试件、洞洞板原型）不在本次范围

> **为什么不做原理图**：用户只布线，不靠原理图。省掉一套 S-expression 就少一份出错面。
> 代价是以后想改拓扑得直接在 PCB 里改。

## 4. 板上元件

坐标系：**PCB 左下角为原点**，单位 mm，Y 向上。板面 98.00 × 50.00。

### 4.1 正面：14 个轴体

**Kailh Choc V2（PG1353）**，原点 = 轴芯中心。**来源：凯华官方规格图。**

> ⚠️ **2026-09-21 修订**：此前本节依据两个开源封装库（daprice / siderakb）「交叉验证」，
> 但实物实测与该表不符 —— **两个库一起错了**（详见任务 #7）。

| 特征 | 孔径 | 数量 | 类型 |
|---|---|---|---|
| 金属电气脚 | **1.20** | **2** | 金属化（PTH）★ 官方图标注 `2-Ø1.20`，通电 |
| 不通电定位脚 | **1.50** | **1** | 非金属化（NPTH），轴体第 3 脚，不导通（官方图 `2*1.5`） |
| 轴芯中心孔 | **5.00** | 1 | 非金属化（NPTH，让位给中央 Ø4.80 塑料凸台） |
| LED 焊盘 | — | 1 | 官方图标注 `LED` |

**★ 三根引脚坐标（2026-09-26 按官方 datasheet 最终落定）**：电气脚 (−3.80, 4.93) 与
(−5.90, 0.00)，不通电定位脚 (5.15, −5.00)（Ø1.50）。依据：凯华官方 datasheet
CPG135301D01（2020-10-23 版）PCB Layout 矢量图像素标定。
⚠️ siderakb 社区封装三孔坐标是官方坐标的 x/y 互换错版，勿引用。

外形 15 × 15 × 5.3mm；底座外形 13.95 × 13.95mm。

14 个绝对坐标来自 `pcb/netlist.json` 的 `keys[].pcb_positions`：

| 行 | 轴体 x | y |
|---|---|---|
| 1 | 13, 31, 49, 67, 85 | 7 |
| 2 | 13, 31, 49, 67, 85 | 25 |
| 3 | 13, **40**, 67（空格）+ 85（语音） | 43 |

> 空格的中间轴在 x = 40，**不在 18mm 网格上** —— 放置时关掉网格吸附，照坐标放。

### 4.2 正面：12 只 1N4148（直插 DO-35）

用户已购**直插**二极管，不用贴片。

| 项 | 值 |
|---|---|
| 封装 | DO-35 玻璃封装，轴向引线 |
| 引脚跨距 | 7.62 mm（预计 KiCad 库名为 `Diode_THT:D_DO-35_SOD27_P7.62mm_Horizontal`，**Step 0 需确认**） |
| 数量 | **12** |
| 安装面 | **正面**（与轴体同侧） |

**为什么必须放正面**：PCB 下方那 5.0mm 已被电池（左，PCB x 0~28）和主控（右，PCB x 79.7~97.5）占用，
剩余 x 28~79.7 还要扣掉 x=40 / 76 两根 ⌀4 支撑台，按行间隙带估算只放得下约 9 只，**不够 12 只**。

**正面的空间**：轴体之间走廊宽 `18 − 13.5 = 4.5mm`，而 DO-35 本体直径仅约 1.9mm。
二极管**沿走廊方向躺放**（7.62mm 引脚跨距顺着走廊走，不横穿），可以放下。
纵向可用高度为 PCB 上表面到定位板下表面的 5.0mm，本体 1.9mm 占得下。

**12 个位置怎么分布**：11 个矩阵位置（9 个单键 + 回车 1 + 空格 1）各 1 只，
加上拨杆 1 只。具体坐标由生成器按 §7 的算法算出。

**方向**：`col2row` —— **阳极接列线、阴极接行线**，电流方向 列 → 行。
12 只必须**统一方向**，接反不会烧但矩阵读不出来。

### 4.3 背面：主控

**NoLogo ProMicro NRF52840**（原名 SuperMini，nice!nano / Pro Micro 引脚兼容）。

| 项 | 值 |
|---|---|
| 尺寸 | 17.78 × 33.00 mm，厚 3.20 mm |
| 安装面 | **PCB 背面（下表面）** |
| 朝向 | 镜像；元件面朝下；USB-C 朝**右壁** |
| 原点位置 | PCB 坐标 **(79.70, 8.50)**（左下角），右缘 97.48，距板缘 0.52 |
| 引脚 | 2.54mm 通孔，引脚朝上穿过 PCB 焊在正面 |

**为什么在背面**：板面被 14 个轴体占满，穷举后正面「零重叠位置数 = 0」。

**引脚分配**（必须与 `firmware/.../claudepad.overlay` 一致）：

| 信号 | 引脚 | 方向 |
|---|---|---|
| ROW1 / ROW2 / ROW3 | D4 / D5 / D6 | 输入（`ACTIVE_HIGH \| PULL_DOWN`） |
| COL1 … COL6 | D7 / D8 / D9 / D10 / D16 / D14 | 输出（`ACTIVE_HIGH`） |
| RGB 数据（留焊盘） | D15 | 输出 |

### 4.4 背面：其余焊盘

`docs/PCB设计规格书.md` §5 只给了这些焊盘的**语义位置**，没给坐标 —— 生成器需自行选位（见 §6.3）。

| 焊盘组 | 数量 | 语义 | 规格书的说法 |
|---|---|---|---|
| 电池 | 2（B+ / B−） | 电池引线焊到主控的 B+ / B− 焊盘 | 「左侧空区」 |
| 电源开关 | 2 | 串在电池正极与主控之间 | 「左侧」 |
| 复位按钮 | 2 | 并联到 RST（该主控无板载复位按钮） | 「主控旁」 |
| 拨杆引线 | 2 | 公共端 → ROW1，常开端 → COL6 | 「右侧缺口附近」 |
| D15（RGB 预留） | 1 | 备将来接 WS2812 | — |

### 4.5 网络清单

| 网络 | 连接 |
|---|---|
| `ROW1` | 主控 D4、PERM、UP、MODEL、CMD、STOP 的二极管阴极、拨杆二极管阴极 |
| `ROW2` | 主控 D5、LEFT、DOWN、RIGHT、回车二极管阴极 |
| `ROW3` | 主控 D6、空格二极管阴极、语音二极管阴极 |
| `COL1` | 主控 D7、PERM 二极管阳极、LEFT、空格（3 轴并联） |
| `COL2` | 主控 D8、UP、DOWN |
| `COL3` | 主控 D9、MODEL、RIGHT |
| `COL4` | 主控 D10、CMD、回车（2 轴并联） |
| `COL5` | 主控 D16、STOP、语音 |
| `COL6` | 主控 D14、拨杆二极管的**阳极** |
| `APPROVE_MID` | 拨杆二极管的**阴极** ↔ 拨杆开关**常开端 NO** |
| `VBAT` | 电池 B+ → 电源开关 → 主控 B+ |
| `GND` | 电池 B−、主控 B−、复位按钮一端、拨杆公共端 |
| `RST` | 主控 RST、复位按钮另一端 |
| `RGB_DIN` | 主控 D15、D15 预留焊盘 |

**拨杆的串联路径**（与矩阵按键同构，方向一致）：

```
COL6 ──▶ 二极管阳极 ──▶ 二极管阴极 ──▶ 拨杆 NO ──[拨杆]── COM ──▶ ROW1
              （APPROVE_MID 是二极管与开关之间的中间网络）
```

**大键并联**：回车 2 个轴体电气并联到同一交点（ROW2 × COL4）；
空格 3 个轴体并联到（ROW3 × COL1）。PCB 上把它们的焊盘用铜箔连到同一条线。

## 5. 板框与缺口

### 5.1 板框

矩形 **98.00 × 50.00**，四角**不做安装孔** —— PCB 由 14 个轴体「挂」着（轴体卡在定位板上，
定位板用 4 颗 M2 螺丝锁在底座上）。

### 5.2 右侧缺口

| 项 | 值 | 状态 |
|---|---|---|
| 深度 | 8.00 mm | ✅ 已定 |
| 长度 | 24.00 mm | ✅ 已定 |
| **纵向位置** | **未知** | ❌ **必须在生成前解决** |

**缺口的用途**：SPDT 拨杆的**本体在壳内**（拨杆 + 轴套 + 螺母在壳外），本体沿轴套方向侵入约 8.5mm。
不给它让位，本体就会压到 PCB 上。

**为什么位置是未知项**：`cad/case_bottom.scad` 第 28 行有 `SW_Y = 16.0`（拨杆中心纵向位置），
但它处于**外壳坐标系**，而缺口要落在 **PCB 坐标系**里。两套坐标的换算关系没有在文档里对齐过，
按 `case_bottom.scad` 第 34–35 行的换算约定（`case = CASE_WALL + PCB偏移 + pcb`）推出来的缺口区间
会超出板边（y 为负），说明 `SW_Y` 可能没跟着历次改动更新。

**更严重的是**：`tools/check_dims.py` 只校验了缺口的**深度**（`PCB_NOTCH_D >= 4.0`），
**从未校验过缺口的纵向位置**。也就是说缺口开错位置，26 项校验照样全绿 —— 这是同一类
「校验过了但不代表对」的陷阱。

**解决要求**：生成前必须确定缺口的纵向区间，并把它固化成可校验的值（进 `params.scad` 或 `check_dims.py`）。
缺口位置错 → 拨杆本体压板 → 板子报废。

## 6. 生成器设计

### 6.1 技术路线

用 **KiCad 自带的 Python + `pcbnew` API** 生成。

```
KiCad/bin/python.exe tools/gen_kicad.py
```

选这条路线的**唯一理由是封装正确性**：`pcbnew.FootprintLoad()` 从 KiCad 官方库加载真封装，
封装几何不由本项目手抄。备选方案（纯 Python 手写 `.kicad_pcb` 文本）虽然不依赖 KiCad 的 Python，
但必须内嵌手抄的封装定义 —— 抄错 1mm，DRC 全绿而板子做废，正是本项目 README 警告的
「自信地展示错误信息」。

### 6.2 输入

只读 **`pcb/netlist.json`** —— 由 `tools/gen_pcb.py` 从 `cad/lib/params.scad` 生成。

现有字段已经足够：

| 字段 | 内容 |
|---|---|
| `keys[]` | 12 个键：`label` / `row` / `col` / `net_row` / `net_col` / `pin_row` / `pin_col` / `switches` / `pcb_positions` |
| `rows[]` / `cols[]` | 网络名到引脚的映射 |
| `pinout` | 行/列/拨杆/RGB 引脚 |
| `diode_direction` | `col2row` |
| `switch_footprint` | Choc V2 焊盘坐标与孔径 |
| `pcb` | 宽 / 高 / 厚 / 原点偏移 / 缺口深度与长度 |

**生成器不得重新计算轴体坐标**。坐标算错一次就有两份不一致的来源。

### 6.3 需要生成器自行选位的部分

`netlist.json` 里**没有**这些焊盘的坐标，生成器必须按语义选定并写死为常量（附注释说明依据）：

- 电池 B+ / B− 焊盘
- 电源开关 2 个焊盘
- 复位按钮 2 个焊盘
- 拨杆引线 2 个焊盘

选位时必须满足：

1. 不与任何轴体本体（13.5mm 见方）重叠
2. 不与 4 个 ⌀4 支撑台（PCB 坐标 (40,16) (76,16) (40,34) (76,34)）重叠
3. 落在板框内
4. 不侵入右侧 8×24 缺口

## 7. 二极管坐标重算（修现有 bug）

### 7.1 问题

`pcb/placement.csv` 当前给出的二极管「建议位」**落在板外**：

```
D1,diode,ROW1xCOL1,13.00,-1.00,PERM；阳极→COL1，阴极→ROW1
```

它是按「轴体正上方 8mm」算的，而轴体在 y = 7，减 8 得 **y = −1**，板是 y 0~50。

### 7.2 修法

把二极管坐标的计算**移进 `tools/gen_pcb.py`**（它已经在算轴体坐标），算法：

1. 对每个需要二极管的矩阵位置，找一个**离对应轴体最近、且合法**的走廊位置
2. 合法性 = 不与轴体本体、支撑台、缺口、板缘重叠
3. 二极管方向统一为 `col2row`

产出写进 `netlist.json` 的新字段（如 `keys[].diode_pcb_pos`），供：

- `gen_pcb.py` 写 `placement.csv` 与 `netlist.md`
- `gen_kicad.py` 放 KiCad 封装

**这样三处共用同一份坐标**，不会各算各的。

| 4 | 定位板开孔 13.80 vs 底座外形 13.95 | 轴体装不进定位板 | 待实物复量；若需改则定位板要重打 |
| 5 | 二极管选位算法产出的位置不合法 | 装不进 | 自检项 ②③ 拦掉 |
| 6 | `pcbnew` API 版本差异 | 脚本跑不起来 | Step 0 侦察；以实际安装版本的 API 为准 |
| 7 | 主控在背面需镜像 | 引脚左右颠倒，固件对不上 | 生成后用自检核对每个引脚的网络与 `netlist.md` 一致 |

## 11. 本设计的边界

**包含**：生成器设计、板上元件与网表、板框与缺口、二极管坐标重算、验证方案、执行顺序。

- 用户已购**直插** 1N4148（不用贴片）
